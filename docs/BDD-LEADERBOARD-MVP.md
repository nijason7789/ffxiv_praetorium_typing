# 排行榜 MVP：需求決議與 BDD 草稿

狀態：需求已依問答記錄，**尚未實作排行榜、命名視窗或版本統計**。後端及技術棧尚未選定；待確認細節另列，不把建議當作已完成的功能。

## 已確認決議

| 項目 | 決議 |
| --- | --- |
| 收錄難度 | 普通、零式、絕；體驗不入榜 |
| 通關條件 | 只收完整通關的成績，部分完成不提交 |
| 玩家身分 | 自訂暱稱，不登入，允許同名；暱稱不是唯一身分 |
| 填名時機 | 開局前填寫，本局使用同一份名字，供未來互動事件、結算與排行榜使用；下一局可修改 |
| 提交時機 | **結算後由使用者手動點擊「送出成績」**；填寫暱稱、完成遊戲或開啟結算頁都不自動提交 |
| 紀錄數量 | 同一玩家可有多筆不同場次紀錄；同一局重試提交只建立一筆 |
| 分榜 | 作答語言＋難度＋題庫版本 |
| 排序 | 分數降冪 → 精準度降冪 → 作答時間升冪；三者相同則並列 |
| 排名用時間 | 從第一個有效作答輸入到最後一題完成，包含題間等待；不直接沿用排除題間等待的 CPM 計時 |
| 首版可信度 | 休閒榜，後端檢查欄位及合理範圍，接受仍可能出現偽造成績 |
| 禁止貼上的定位 | 現有普通／零式／絕禁貼規則保留，但不能取代成績驗證 |

排名所用的精準度比較精度尚待定義，不能先默認為畫面已四捨五入的百分比。未來互動事件僅先記錄方向，本次不新增事件、獎勵或計分規則。

## 開局取名視窗

以 radio button 選擇命名規則，**與作答語言完全獨立**。例如使用繁中服命名格式的玩家也能選擇英文或日文題庫。

| 命名格式 | 欄位與限制 |
| --- | --- |
| 繁中服命名格式 | 單一姓名欄位；中文或英文都最多 6 個字元 |
| 國際服命名格式 | 名字、姓氏兩個欄位；各 2～15 個字元，合計最多 20 個字元，顯示時以空格連接 |

切換 radio button 時更新欄位、字數提示與驗證規則；不改變作答語言或遊玩版本。切換時是否保留先前輸入值、預設命名格式，以及完整允許字元清單仍待確認。

可使用蓋烏斯語氣呈現，例如「冒險者，報上你的名字。」及「以此名開始試煉」；此處是文案草案，不固定為最終文字。

### 官方資訊與本專案規則的界線

- [繁中官方遊玩手冊](https://www.ffxiv.com.tw/web/intro/guide/game_manual/start/)：姓名最多 6 個字元。使用者亦確認英文同樣受此上限限制；不能解讀為中文 6 字、英文另給 20 字。
- [國際服官方 FAQ](https://support.na.square-enix.com/faqarticle.php?id=5382.&kid=67258)：名字與姓氏各 2～15 個字元，合計最多 20 個字元，以空格分隔顯示。
- 繁中手冊未完整列出允許字元；國際服的符號位置限制、合計上限是否計入分隔空格，以及本專案採用的字元計數方式，仍需在實作前明確規範。
- 排行榜允許同名，不沿用遊戲內同一 World 名稱不可重複的限制，也不宣稱驗證了玩家的遊戲角色身分。

## 遊玩版本：選填統計欄位

取名視窗增加「遊玩版本」下拉選單：

1. 未選擇（預設）
2. 繁體中文版
3. 國際版
4. 簡體中文版

未填不阻止開始遊戲，資料記為「未提供」，不依作答語言、命名格式或瀏覽器語言推測。

此欄位供版本分布統計，**不作為排行榜分榜條件，也先不公開個別玩家的遊玩版本**。公開排行榜資料與統計欄位需區分，不能直接將整份提交資料公開列出。

統計的蒐集時機及分母仍待確認：若只隨手動提交成績送出，只能描述「已提交場次」的版本分布，不能稱為所有玩家或所有開局的分布。同一玩家多次遊玩也不能直接當作多位不同玩家。

## BDD 驗收草稿

U＝純規則，I＝介面／控制器整合，API＝後端整合，B＝瀏覽器驗收。以下是預期，尚未建立對應測試。

| ID | Given 前提 | When 行動 | Then 預期 | 層級 |
| --- | --- | --- | --- | --- |
| NAME-01 | 選擇繁中服命名格式 | 輸入超過 6 字元的中文或英文姓名 | 顯示長度錯誤，不因英文而放寬上限 | U / I |
| NAME-02 | 選擇國際服命名格式 | 名字或姓氏不在 2～15 字元內，或合計超過 20 | 無法以該姓名開局，指出不符合的限制 | U / I |
| NAME-03 | 已選作答語言及填寫遊玩版本 | 切換命名格式 | 只更新姓名欄位、提示與驗證；其餘選擇不連動 | I / B |
| NAME-04 | 本局已開始 | 顯示互動訊息、結算或準備提交 | 使用開局時固定的暱稱，不被下一局的編輯追溯改寫 | I |
| EDITION-01 | 遊玩版本維持未選擇 | 以有效暱稱開局 | 允許開始；版本為未提供，不自動推測 | U / I |
| EDITION-02 | 相同語言、難度與題庫版本，不同遊玩版本 | 檢視排行榜 | 不因遊玩版本另行分榜，也不公開個別版本欄位 | API / I |
| RANK-01 | 開局已填暱稱 | 完整通關並顯示結算 | 不自動向排行榜提交成績，等待手動點擊送出 | I / API |
| RANK-02 | 體驗完整通關或其他難度部分完成 | 嘗試提交成績 | 介面不提供有效提交操作；後端也拒絕不合資格資料 | I / API |
| RANK-03 | 普通／零式／絕完整通關 | 手動點擊送出成績 | 使用已鎖定的本局成績與暱稱提交，過程不改變結算結果 | I / API |
| RANK-04 | 同一局正在提交或回應遺失 | 重複點擊或重試提交 | 後端對同局請求去重，只建立一筆紀錄 | API / I |
| RANK-05 | 同一暱稱或同一玩家完成不同場次 | 各局分別手動提交 | 允許新增多筆，不以暱稱合併或覆蓋他人成績 | API |
| RANK-06 | 不同作答語言、難度或題庫版本 | 查詢排行榜 | 分別列入對應榜單，不混合比較 | U / API |
| RANK-07 | 同一榜內有多筆紀錄 | 排序 | 依分數、精準度、作答時間比較，完全相同並列 | U / API |
| RANK-08 | 首次有效作答後有題間等待 | 完成最後一題 | 排名時間包含中間等待，排除開局前填名與結算後等待 | U / I |
| RANK-09 | 完整通關，但提交失敗 | 留在結算頁並重試 | 保留本局成績及輸入，顯示失敗狀態，不重開場次、不重複新增 | I / API |
| RANK-10 | 提交欄位缺失、型別錯誤或超出已定義合理範圍 | 呼叫 API | 後端拒絕；不依賴前端驗證，也不宣稱可完全防止作弊 | API |

## 尚待確認

1. 命名細節：允許字元、繁中最短長度、空白整理、Unicode 字元計數、國際服分隔空格是否計入上限，以及切換格式的欄位保留方式。
2. 入榜場次：普通模式的打字／填空／混合是否都收錄、是否限定全劇本，以及章節練習、單句原型、略過標點與 RPG 加分的處理。這些條件可能影響分榜或資格，不能先混在一起。
3. 有效作答的起點、背景頁／全文閱讀時間是否扣除、同分精準度與時間的比較精度、並列後下一名的名次編號。
4. 統計是否只蒐集已手動提交的場次；若包含未提交的遊玩，需另外定義告知、蒐集時機及資料保留方式。
5. 投稿公開欄位、異常紀錄隱藏／移除方式、提交頻率限制與錯誤回覆細節。
6. 後端合理範圍、同局去重識別、資料儲存與 API 技術棧。暱稱及格式都不能充當唯一場次識別。

## 後續順序

先補齊上述會影響資料公平比較的決議，再確定資料格式與 BDD 情境；接著選後端技術棧並實作最小版本。遊戲中動態事件另立需求，先預留本局暱稱的使用，不在這一批變更既有計分。

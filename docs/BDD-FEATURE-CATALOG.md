# 功能盤點與 BDD 測試清單

盤點基準：`e1c2c85`。本文件依目前 `index.html`、`src/`、`tests/` 與部署 workflow 整理，作為後續 refactor 前的行為討論與測試待辦。

這是功能與驗收情境清單，不代表所有情境都已有測試。2026-10-30～31 的 27 題問答已確認原先 13 項決議；第 3、4 節已同步納入確認後的預期，第 7 節保留原始觀察與決議追蹤。已確認規格不代表程式已修改或測試已通過。

## 1. 使用方式

1. 選一個功能 ID，確認其 Given／When／Then 是否符合想保留的行為。
2. 若涉及第 7 節，依已確認規格撰寫驗收測試；若要記錄舊程式的不同結果，另外標示為現況測試。
3. 用穩定的功能 ID 連結情境、測試與修正，例如 `it("[DECK-02] 重進頁面後接續尚未抽完的詞庫", ...)`。
4. 先補能保護外部行為的測試，再抽離內部模組。重構後可更換呼叫方式，但保留同一條驗收規則。
5. 新增功能時同步更新清單；一個情境可對應多個測試，不要求一列只能有一個 `it`。

BDD 的重點是先描述使用者可觀察的行為，再用測試驗證。現有 Vitest 的 `describe`／`it` 即可採用這種寫法，無須新增 BDD 套件。首批測試與實作進度見第 9 節。

### 測試層級

| 標記 | 層級 | 適合驗證的內容 |
| --- | --- | --- |
| U | Unit | 純規則、輸入輸出、計算、抽題順序；不依賴整份 HTML |
| U* | 可抽離成 Unit | 目前與 DOM／全域狀態耦合，先以整合測試保護，再抽成純函式或可注入依賴的單元 |
| I | Integration | 操作事件、狀態、DOM、儲存或音訊介面的合作；可用 happy-dom 與替身 |
| B | Browser | 真實鍵盤／IME、焦點、響應式版面、媒體解碼與播放、瀏覽器權限 |
| O | Operations | CI、建置產物、部署與公開網站驗證 |

`U* / I` 不是說目前已有單元測試；它表示產品規則適合拆成單元，但當前仍需整合測試。不要為了把測試命名為 Unit 而 mock 掉待驗證的整段行為。

不必建立整個矩陣的笛卡兒積。純語言規則參數化測三語；主流程選代表性組合；跨模組問題再增加針對性的組合。

## 8. 建議補測順序與 refactor 邊界

| 優先序 | 先保護的情境 | 可形成的單元邊界 |
| --- | --- | --- |
| P0 | 文字比對、標點、判定整句完成、重複完成防護、舊換題取消 | `evaluateTyping`、可取消的場次轉移 |

| P0 | 填空輪替、讀寫失敗、重新載入、有效候選、答案驗證 | 抽題規則與儲存 adapter 分離 |
| P1 | 語言→難度→遊戲、章節／模式、重開、難度限制 | 場次狀態與 UI controller 分離 |
| P1 | 空答案、IME、RPG 防重、複製成功／失敗 | 輸入提交規則、互動獎勵、剪貼簿 adapter |

上表名稱是候選邊界，不是要求 refactor 一定沿用的 API。要保護的是「行為」，不是檔案位置、函式名稱或目前實作步驟。

### 撰寫測試時的約定

- `describe` 以 Feature／Rule 分組，`it` 以情境與可觀察結果命名；可在註解區分 Given、When、Then。
- 隨機性可注入 RNG 或用可控制的替身；驗證「集合、輪內唯一、跨輪不連續重複」，不要斷言某次真亂數一定產生特定排列，也不要用大量抽樣的機率門檻作為 CI pass 條件。
- 時間使用可控制時鐘；測試等待期間、取消與晚到回呼，不靠真實睡眠等 15 秒。
- 規則單元不載入整份 HTML；UI 整合情境才需要 DOM fixture。
- 計分情境直接用明確的 Given 數字驗證期望結果，避免測試再抄一遍產品公式算 expected。
- 替身放在時鐘、RNG、儲存、剪貼簿、media、Web Audio 等邊界；不要把被測的規則函式整個 mock 掉。
- 每個 Scenario 清除自身狀態、儲存、計時器與事件，並能單獨執行。例外是刻意驗證「跨次／跨分頁」的情境，其前提也應由該情境自己建立。
- DOM 測試可以驗證語意、可見性、disabled 與結果文字；避免把整頁 HTML snapshot、Tailwind class 順序或私有呼叫次數當作主要驗收。
- Browser 測試至少保留一條完整流程：選語言 → 選難度 → 打字／填空 → 結算；另驗證真實 IME、媒體與 Pages 子路徑。這些不能靠 happy-dom 取代。
- 增加 BDD 覆蓋後，仍依專案指引執行 `npm test` 與 `npm run build`；文件盤點本身不等於測試已實作。

### 使用者手動驗收
